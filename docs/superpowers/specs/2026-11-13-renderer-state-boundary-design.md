# Renderer State Boundary Design

## Intent

墓石の見た目をゲーム状態から外し，Rendererが読み取り専用のGameStateと安定IDだけで描画できる境界にする．既存の描画順，スプライト，操作感は維持する．

## Approach

- `BlockState`には初期グリッド位置を使った安定IDを追加し，`sprite`を削除する．IDは移動中も保持され，同じStageの再生成でも同じ値になる．
- Rendererはモジュール初期化時に乱数シードを1回だけ決め，`stageIndex`とBlock IDから壁・苔の画像番号を決定する．対応表やリトライ同期は持たない．
- 墓石の重なりは，横移動中だけ移動先の列を使う既存仕様を1つの位置関数へ集約する．
- タイトル画像の番号は入力割り当てと逆順であり，現行の補正を外すと操作表示が変わる．ピクセル単位で同等な修正版アセットがないため補正描画は維持する．
- 描画値は意味を持つ調整値だけを定数化し，音声メタデータのように既に用途が名前で明確な値は変更しない．

## Alternatives

- Rendererの`Map`でBlock IDごとの画像番号を保持する案は単純だが，初回描画まで見た目が決まらず不要な状態管理が増えるため採用しない．
- 位置をIDとして使い続ける案は移動後に見た目が変わるため採用しない．
- タイトルの入力割り当てを画像に合わせる案は操作仕様を変えるため採用しない．

## Constraints

- `renderer/index.ts`と`audio/index.ts`の公開API，モジュール構成，描画順を維持する．
- RendererはGameStateを変更しない．
- 検証は既存単体テスト，型チェック，Lintだけとする．
